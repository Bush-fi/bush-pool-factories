# StableSurgePoolFactory — Gas Characteristics

Numbers below are taken verbatim from the copied Hardhat gas snapshots in
`test/gas/.hardhat-snapshots/` (generated by `test/gas/StableSurgePoolBenchmark.test.ts`),
run against the actual Solidity contracts — not estimates.
"Warm slots" / "cold slots" have the same meaning as in `stable-pool-factory`'s gas docs
(prior storage access in the same test vs. first touch). The surge-pool benchmark suite
is a smaller subset of scenarios than the plain `StablePool` suite (it omits nested-pool
and several unbalanced-add/remove/single-token variants), reflecting what was actually
captured in the copied snapshots — no numbers below are invented.

No dedicated "pool creation" (factory `create()` call) benchmark exists in the copied gas
suite — the closest proxies are the `initialize` figures below.

## Comparison to plain StablePool (surge overhead)

The surge hook adds a `shouldCallComputeDynamicSwapFee` call (which recomputes the
imbalance before and after the swap via `StableSurgeMedianMath.calculateImbalance`,
including an in-memory sort) plus `shouldCallAfterAddLiquidity` /
`shouldCallAfterRemoveLiquidity` checks. Comparing equivalent scenarios against
`stable-pool-factory`'s benchmarks (same "Standard"/"WithRate" categories):

| Scenario | StablePool | StableSurgePool | Delta |
|---|---|---|---|
| Swap, single token, warm slots (Standard) | 164.9k | 196.9k | +32.0k |
| Swap, single token, cold slots (Standard) | 178.8k | 207.4k | +28.6k |
| Swap, BatchRouter, warm slots (Standard) | 180.2k | 212.2k | +32.0k |
| Add liquidity proportional (Standard) | 179.5k | 190.0k | +10.5k |
| Remove liquidity proportional (Standard) | 166.2k | 176.5k | +10.3k |
| Donation (Standard) | 171.2k | 188.4k | +17.2k |
| Initialize without ETH | 336.2k | 336.2k | 0 (hook not invoked pre-liquidity) |

Swaps carry the largest overhead (~+28k–32k gas) since every swap recomputes the dynamic
fee via the median/imbalance calculation, both pre- and post-swap. Add/remove liquidity
overhead is smaller (~+10k) since the surge check there only runs for non-proportional
operations, and proportional operations short-circuit early in `onAfterAddLiquidity` /
`onAfterRemoveLiquidity`.
